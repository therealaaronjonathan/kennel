## Current Features

### Reception
- Check-in flow (search/register owner + pet, select doctor, assign token)
  - **Phone-first search**: Owner Phone is now the primary search field (always visible at top). Entering a complete 10-digit number and tapping Search returns all pets for that owner — no pet name or species required. Species + Pet Name remain available below as an optional narrowing path (species + name still required when searching by name without a phone number).
  - Phone entered in search pre-fills the phone field when registering a new patient
  - **Pet gender**: Male / Female toggle in the new-owner registration form (required); saved to the pet record in Firestore
  - **No duplicate owners**: phone is the owner's identity — registering a "new" pet on a phone already on file attaches the pet to the existing owner instead of creating a second owner record
  - **Add another pet**: phone-search results are grouped by owner with an "Add another pet" button per owner (pet-only form, owner read-only) → straight into check-in; a no-match name search on a known phone offers "Add pet under {name}" with the typed pet name pre-filled
  - **Edit owner details**: a pencil on the owner header (search results + found card) opens a dialog to fix the owner's name, email, and alternate phone; name edits cascade across all visits, primary phone stays read-only
- Queue view (all visits today, real-time updates); right panel shows Diagnosis → Consultation Notes → Prescription → Vaccines → Services; click empty space to close panel
- **Receptionist mark complete**: for `waiting` or `in-progress` visits, a banner in the detail panel exposes a "Mark as Complete" button; clicking opens a modal confirm dialog — confirming sets `status: 'completed'` and moves the visit to the checkout tab (used when the doctor completes the visit outside the app)
- Queue page has a Payment filter (All / Cash / Card / UPI) and a **Doctor filter** — appears when more than one doctor has visits today; filters are independent
- Right panel header shows visit date & check-in time prominently (e.g. "18 May 2026 · 10:35 am")
- Billed visits expose a "Change payment method" action in the right panel (preserves `billedAt`)
- Check-out/billing: tapping **Mark Billed** opens a confirm dialog showing the bill total and a Cash / Card / UPI picker (no default — must tap one); confirming writes `paymentMethod`, `billAmount`, `billedAt`, and `status: 'billed'` in a single update. WhatsApp summary link with clinic name and production URL.
  - **Edits survive navigation**: in-progress service edits in the checkout panel persist to `sessionStorage` per visit, so switching to Check-in and back (or refreshing the tab) doesn't discard them; cleared on successful billing. Tab-scoped only — the list-row amount still reflects saved services until billed.
- **Billing Defaults**: visits that can't be settled in one day can be pinned to a persistent "Billing Defaults" section at the top of the Checkout tab. Receptionist taps "Pin to billing defaults" in the detail panel footer; the visit stays visible across days in the purple-tinted section regardless of payment state. Pinned visits are automatically removed when fully paid. Removal is manual only by the owner (Firestore). Stored in `clinics/{clinicId}/branches/{branchId}/billingDefaults/{visitId}`, capped to 50 items.
- **Pet details in panels**: Queue, Checkout, and History detail panels now show species, breed, age, and color/marking below the owner/doctor name line. Checkout panel also shows weight at time of visit in the header. Data is fetched from `clinics/{clinicId}/pets/{petId}` in parallel with other detail reads.
- **Detail panels restructured + owner phone**: the shared visit detail panel (Queue/Dashboard/History) and the Checkout panel are now grouped into ordered sections — Owner → Pet → Visit → Clinical → Services. The owner's phone shows as a tappable `tel:` link with a Copy button (falls back to `—` when absent).
- **Edit pet / owner name**: a pencil next to the pet and owner name (in those same panels) opens a small dialog to correct a misspelt name. The fix updates the canonical pet/owner record and backfills the denormalized name on every visit for that pet/owner across branches, plus matching billing-defaults and payment-ledger snapshots — so the correction shows everywhere, including already-shared summary links.
- **Payment ledger (daily money tally)**: every payment is recorded as a dated row in a `payments` collection, so the History "Total Earned" and "By Method" KPIs count money on the **day it was received** — a partial paid across several days (billing-defaults case) now lands on the correct days instead of all on the visit's creation date. Per-visit paid status is unchanged (still read from the visit). "Visits Completed" stays visit-based.
- Home dashboard (stats, doctor cards, recent completions)
- Settings (duty roster, catalogs: diagnoses, medicines, services)
  - **Diagnosis delete**: diagnoses are now hard-deleted from Firestore (permanent removal). UI shows an inline two-step confirm before deleting. Past visit records are unaffected — diagnosis names are stored as text snapshots on visits.
  - **Medicine type at creation**: the Add Medicine form (Settings and Admin → Catalogs) now has a Tablet / Syrup / Injection selector (defaults to Tablet); each medicine row shows a type badge. The type drives the quantity control the doctor sees when prescribing. Legacy typeless medicines read as Tablet.
- Branch name shown in sidebar (static label or dropdown switcher for multi-branch)
- Stacked notification toasts with sound: "Call Patient" (in-progress) and "Consultation Complete" (completed)

### Vet Console
- Queue sidebar (waiting patients, real-time)
- Consultation form (diagnosis, prescription, vaccines, services, notes)
  - Medicine catalog has `type` field: `tablet` | `syrup` | `injection` (injections include vaccines)
  - Prescription card: full-width Morning/Afternoon/Evening/Night toggle buttons; Quantity + Duration side-by-side
  - Tablet quantity: Full / Half / 1/3 / 1/4 dropdown
  - Syrup quantity: ml dropdown (2.5 → 30 ml)
  - Injection quantity: free numeric input (ml/units)
  - **Multiple vaccines per visit**: vaccine section is now a list — add/remove rows, each with its own name, batch number, and next-due date; saved as separate subcollection docs. Selecting a vaccine auto-adds its service line item to Services (increments quantity if already present); removing a vaccine decrements/removes the corresponding service
  - Vaccine "Next Year" toggle — auto-sets next due date to same day next year (per row)
- Mark in-progress / pause / complete — Mark Complete now validates the form before opening the confirmation: each prescribed medicine must have at least one timing, a valid quantity, and `days ≥ 1`; vaccine accordion is treated as "in use" if any field is filled, in which case Name and Next Due become required (Batch stays optional). Invalid fields render with red borders + helper text, and the button smooth-scrolls to the first offending field.
- **Vitals row**: weight (kg) and temperature (°F) shown side-by-side at the top of the consultation form; `petWeightKg` and `petTemperatureF` saved on the visit doc; surfaced in the last-visit panel and all detail panels (Queue/History/Checkout)
- **Before/After food for medicines**: optional per-medicine toggle in the prescription card (two-column Before food / After food toggle below qty/days); saved as `mealTiming: 'before' | 'after'` on the prescription doc; shown in the dosage display in the detail panel and in the shareable link
- **Token reassignment**: vet-only action to hand a waiting or in-progress visit to another on-duty doctor. For in-progress visits, a **Reassign** button appears in the footer next to Pause; for waiting visits, a "Reassign to another doctor" link appears above the form. Both open a doctor-picker dialog listing only doctors currently marked on-duty by the receptionist (from the duty roster). Confirming saves the current consultation draft (so the receiving vet inherits any notes already entered), updates `doctorId` / `doctorName`, and resets `status` to `'waiting'`. The button/link is hidden when no other on-duty doctors are available.
- Last visit panel — collapsed by default, with an always-visible header showing date, relative time ("2 weeks ago"), doctor name, and ER / visit-type pills. Tapping expands a structured body: Complaints, Diagnosis, Doctor's Notes, Medicines (with type pill + dose + timing/days), Vaccines (with red **Overdue** pill when next-due is past), Services + Total, Payment method. A "View N earlier visits" modal lists every prior visit; tapping a row opens that visit's summary page in a new tab.
- Pet header now also surfaces color and microchip number when recorded.
- **History access**: a "History" link in the top-left of the vet console (next to the branch name) opens the full front-office History tab as a full-screen overlay. Closed via "← Back to queue". Same component and data as the receptionist History tab.
- Branch name shown in top bar (switcher for multi-branch)

### Auth & Routing
- Email + password login
- Google OAuth
- Role-based routing: doctor → `/vet`, receptionist → `/reception/home`, admin/owner → `/admin`
- **Role-based route guards**: `/admin` is locked to admin/owner, `/vet` to doctor, `/reception/*` to receptionist/admin/owner. Mismatched roles are redirected to their own role's home (no leaked access via stale URLs).
- **Back-button trap on authenticated routes**: a popstate listener re-pushes the current URL so the browser back button can't escape the app once signed in.
- Logout flows use `navigate('/login', { replace: true })` so the previous authenticated route is cleared from history (no role-bleed when a different user logs in next).
- Multi-branch selector screen (`/select-branch`) for staff assigned to multiple branches
- Legacy staff docs without `role` field handled gracefully

### Admin Panel
- `/admin` dashboard
- Clinic management: create/edit clinics with white-label branding (colors, logo, tagline)
- Branch management: add/edit branches per clinic
- Doctor management: invite doctors via backend API (Firebase Auth + Firestore + invite link); inline edit per doctor (name, phone, bio, profile photo via Firebase Storage upload, branch assignment); doctor rows show avatar (photo or initials) and branch tags
- Staff management: invite receptionists via backend API; inline edit per staff member (name, phone, branch assignment); staff rows show branch tags; reads from `clinics/{clinicId}/staff` subcollection
- Catalog management (4 tabs): Diagnoses, Medicines, Services, Grooming. Medicines tab has a Tablet / Syrup / Injection type selector at creation + per-row type badge.

### Consultation Summary Page
- Public route: `/visit/:visitId/summary?clinicId=...&branchId=...`
- White-label branding from clinic config
- Shows diagnosis, prescriptions, vaccines, consultation notes
- Print button
- WhatsApp checkout message includes the summary link
- **Services & Payment section** (finished visits — `completed` or `billed`): itemized service list with quantities and prices, grand total, and payment method(s) displayed inline. Shows for `completed` (unpaid) visits too so customers can review charges before paying; in that case a "Payment pending — please settle at the clinic." note replaces the payment breakdown. Section is hidden when no services are recorded or the visit isn't finished
- **Pet weight**: shown in the consultation meta grid when recorded
- **Full pet details**: Breed (Pet Breed), Age (Pet Age), and Color/Marking (Pet Color / Marking) are now shown in the meta grid when recorded; fetched from the pet doc via `petId` on the visit. Labels use the "Pet" prefix for clarity.

### Backend API (`apps/backend`)
- Bun + Elysia layered architecture
- `POST /api/admin/users` — create Firebase Auth user + staff doc + doctor doc, returns invite link
- `PUT /api/admin/users/:uid` — update branchIds/role/isActive/name/phone/bio/photoUrl; writes atomically to both root `staff/{uid}` and clinic-level `doctors/{uid}` or `staff/{uid}`
- `DELETE /api/admin/users/:uid` — disable user
- Auth middleware: verifies Firebase ID token, checks admin/owner role

### Firestore Security
- Public read access on visits, clinic branding, branch info, and visit subcollections — enables unauthenticated owners to open queue and summary links on mobile
- All other paths (petOwners, pets, catalogs, staff, tokenCounters) require authentication
- Rules live in `firestore.rules` at repo root, deployed via `firebase deploy --only firestore:rules`

### Token System
- Branch-wide sequential counter (`tokenCounters/{date}` under branch)
- Token prefix = last 3 chars of doctor's last name (e.g. `ESH-0001`)
- Resets daily; counter doc auto-created on first check-in
